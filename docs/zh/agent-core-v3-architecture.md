# Agent Core V3 架构

[English](../en/agent-core-v3-architecture.md)

## 设计目标

Agent Core V3 为学生 AI 助教和教师 AI 题目草稿提供可审计、可约束、可恢复的统一运行架构。模型负责语言理解与受限规划，服务器负责身份、授权、数据范围、工具执行、比赛策略、预算与最终输出检查。

核心假设是：**模型是不可信规划器，服务器是可信控制面**。模型输出不能直接改变权限、读取任意数据、执行任意工具或写入长期记忆。

## 在线 Turn

```text
用户请求
  -> 服务端建立 Turn 与身份/策略快照
  -> 构建最小 Bootstrap Context
  -> 模型提出回答或工具请求
  -> 服务端逐次授权并执行工具
  -> 汇总受信数据与模型输出
  -> 输出安全检查
  -> 持久化回答、用量、工具与审计证据
  -> 异步生成可检索摘要
```

每个 Turn 有稳定 ID 和终态。重试按 Turn 幂等，避免重复计费、重复审计或重复记忆候选。Provider 失败、工具失败或摘要延迟不会绕过服务端策略。

### 流式事件

`/ai/chat/stream` 除 `meta`、`context`、`message`、`done`、`error` 之外，还有两类事件：

- `delta`：`{"text","step"}`，正文增量和它所属的模型调用序号；
- `tool`：`{"phase","step","name","status","durationMs"}`，工具开始和结束，不带参数，也不带结果。

练习轮向 Provider 发起流式调用，思考内容不转发。某一步一旦出现可能属于内部协议的字符（`{`、双引号、反引号），这一步余下的正文只经最终的 `message` 送出。交付前的比赛状态重检通过之后，服务端才把缓冲的事件发给客户端，所以客户端收到增量不早于整轮完成；内容以 `message` 为准。比赛受限轮不流式，输出检查通过后切片回放。断线续接不补发已经过去的增量。

## 上下文分层

原始会话与业务数据始终是权威源；摘要、索引、向量和记忆都是派生数据。

1. **Bootstrap Context**：当前用户、会话、题目、比赛和能力边界的最小可信摘要。
2. **Turn 摘要**：每轮结构化记录主题、实体引用、决定与未解决问题。
3. **Episode 摘要**：跨多轮的阶段性上下文。
4. **原始证据回取**：回答关键事实前回取受权原文或业务记录。
5. **精确检索兜底**：摘要召回不足时使用受限关键字或实体检索。

检索结果携带来源、范围和可信等级。未经验证的模型陈述不能被提升为用户事实。

## 工具控制面

模型只看到当前场景允许的工具描述。每次调用都由服务器重新检查：

- 当前用户与角色；
- 当前会话、题目、比赛运行和时间窗口；
- 工具参数 Schema；
- 数据可见性与最小返回字段；
- 调用预算、超时和循环上限；
- 审计与隐私要求。

工具结果使用结构化数据并标注可信来源。网页、题面、用户内容和模型文本都不能作为系统指令改变工具权限。

### 助教的代码工具

问答场景有三个代码工具：`code.compile_check`、`code.run_samples`、`code.run_custom`。代码只取自本轮选中的代码、题目页编辑器随本轮发来的代码，或学生本人的提交，由服务端绑定，模型只能指明来源，不接受模型给出的源码；执行经 agent-executor 进入 agent-sandbox，编译结果按调用者隔离缓存。结果是统一的执行反馈：判定、耗时、内存、进程峰值、与期望输出的第一处不同、编译诊断或 stderr 摘要。比赛受限轮看不到这三个工具。

### AI 题目草稿场景

AI 题目草稿路径复用同一 `AgentRuntime` 与 agent-harness 工具运行时，不再运行固定七阶段模型流水线，也不复制第二套 Agent 循环。每道题使用独立持久化 workspace 和专用 `problem_draft_agent` 会话，模型通过九个草稿工具读取、修改、静态校验、执行代码、运行样例、生成/验收测试包并请求最终化；服务器绑定资源并执行所有门禁。旧同步、SSE 和重新生成入口已转接持久 Agent 作业。真实 DeepSeek + Docker 联合链路已在本地完成 CF 800、1400、1800 三档验收（2026-08-15 一次，2026-10-29 在 agent-executor 执行路径上又一次），均生成 `PENDING_REVIEW`、`AGENT_VERIFIED` 草稿；生产环境仍为 `IMPLEMENTED_UNVERIFIED`。完整设计见 [AI 题目草稿 Agent 架构](problem-draft-agent-architecture.md)。

DeepSeek 思考模式的 `reasoning_content` 只在当前工具循环内存中完整回传。它不进入数据库、日志、审计或前端；思考不可用时，允许草稿场景显式降级到标准工具循环并记录 `STANDARD_TOOL_FALLBACK`。

## 记忆与学习画像

长期记忆保存稳定、可复用且有证据的用户偏好或事实；学习画像保存从提交、复盘和行为信号推导的能力状态。两者分离，避免把一次题目知识点或 AI 建议误当作长期偏好。

```text
证据 -> 候选 -> 质量/冲突检查 -> 用户确认 -> 生效 Claim
```

模型只能提出候选。服务端保存证据、来源和状态；用户可以接受、拒绝或撤销。冲突 Claim 不静默覆盖，画像信号保留时间与来源。

轮次结束后，摘要整理、向量化、画像聚合、判题分析和记忆合并审查都经统一数据通道异步完成，每个订阅者有自己的作业、重试和死信，一个订阅者失败不影响其他订阅者，也不影响已经交付的回答。学生否认、标记失信或重新启用一条画像，是经画像端口的同步写入。

## 比赛安全

比赛防护使用四层服务端边界：

1. **参赛判定**：服务器根据当前运行、参与者和时间窗口判断约束范围。
2. **策略快照**：将运行发布时固化的 AI 策略注入当前 Turn。
3. **问题匹配**：使用运行题目快照与受限指纹判断用户是否在询问比赛题。
4. **输出检查**：返回前检查完整代码、私有题信息与其他受限内容。

客户端传入的 `problemId` 或比赛上下文只用于体验和统计，不能作为可信授权依据。私有题面、隐藏测试和其他参与者源码不会发送给模型用于判断。

## Prompt Injection 防护

- 指令权只来自可信服务器配置和受控策略。
- 用户文本、历史消息、题面、工具结果和检索内容都标记为数据，不可修改系统权限。
- 工具返回结构化字段，不拼接成可执行系统指令。
- 记忆写入经过独立候选与确认流程。
- 最终回答在返回前执行内容与策略检查。

## 审计与用量

每轮保存必要的模型调用、Token 用量、工具调用、策略决策、降级状态和追踪关联。审计只保留安全摘要，不记录密钥、隐藏测试、完整内部错误、原始模型思考、执行代码或无关个人数据。

比赛 AI 用量按服务端可信运行归属统计对话轮次、输入/输出 Token、会话数和拦截数；统计观察不改变回答、配额或 Agent 规划。

## 失败与降级

- Provider 不可用：返回安全、可追踪的降级错误，不伪造 Token 或事实。超时、重试和熔断由模型调用包统一处理；流式调用已经产生输出后失败，不再重试。
- 工具超时或执行器不可用：停止该调用并保留审计，结果作为数据交回模型，这一轮继续；不能绕过权限改用数据库直读。
- 记忆、画像或其他可选上下文段失败或超时：只缺这一段，这一轮照常回答；比赛策略段失败则按策略拒答。
- 降级记录：每次模型调用的上下文 manifest 记下降级的上下文段（`contributor_degraded:<段>:<原因>`）和基础设施失败的工具（`tool_degraded:<工具>:<状态>`）。
- 摘要或索引延迟：回退到授权的近期上下文或精确检索。
- 比赛策略依赖异常：遵循安全默认并记录降级证据。
- 输出检查失败：拒绝或收敛输出，而不是返回未检查内容。
