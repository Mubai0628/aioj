# 安全架构

[English](../en/security-architecture.md)

## 目标

AIOJ 同时处理不可信用户代码、身份凭据、隐藏测试、比赛题目、参与者源码和 AI Provider 数据。安全架构采用最小权限、服务端授权、数据最小化、异步隔离、可审计性和纵深防御。

## 数据分类

| 数据 | 保护要求 |
| --- | --- |
| 密钥、令牌、数据库凭据 | 仅服务器秘密存储，禁止进入 Git、镜像层、日志与客户端 |
| 隐藏测试与测试包 | 文件/卷存储，按题目与判题任务授权，禁止公开下载 |
| 参与者源码 | 学生本人可见；教师访问使用受审计 API；查重导出默认不含完整源码 |
| 私有比赛题面 | 仅符合运行参与者与时间策略的请求可见 |
| AI 对话、记忆和画像 | 最小收集、按用户授权、可追踪来源，候选需用户确认 |
| 评测输出 | 客户端只接收产品所需摘要，内部完整输出受限且有边界 |

## 身份与授权

网关是浏览器入口，但最终业务授权由目标服务执行。JWT、角色和资源归属共同决定权限；内部服务令牌不能替代用户级资源检查。前端隐藏按钮不是安全控制。

内部接口使用按调用方向隔离的 `X-Internal-Token`：ai → problem、judge → problem、problem → ai、problem → judge 各有独立随机令牌；ai → agent-executor 沿用执行器专用令牌。网关和 auth-service 不持有这些令牌。被调服务使用定长摘要比较来识别调用方，再按路径段前缀白名单授权；缺少或未知令牌返回 401，已识别但无权访问的前缀返回 403，未登记前缀默认拒绝。前缀按服务器规范化后的路径匹配，带 `..` 或 `;` 的写法不能绕开检查；没有 Spring Security 的 judge-worker 和 agent-executor 在控制器里再校验一次令牌。普通 JWT 不能替代内部凭据。已废弃且无调用方的 contests ai-policy HTTP 入口已移除。

令牌只配置在需要它的服务中，旧共享 `AIOJ_INTERNAL_API_TOKEN` 不再用于应用通信。入站支持当前值和可选 `*_NEXT`，出站只用当前值；先更新被调方的 NEXT，再更新调用方，最后提升被调方当前值并清空 NEXT，每步只重启一个服务。生产使用独立的高熵随机值，不从同一共享秘密派生；缺少必需变量时生产 Compose 拒绝启动，本地空值则 fail-closed。日志只记录调用方、路径和拒绝原因，不记录凭据。

## 限流

- 网关只在连接来自可信代理时才读 `X-Forwarded-For`，并且只取从右往左数第 N 项（N 是网关前可信代理的层数，默认 1，即 web 的 nginx），左边客户端自己填的项不算。结果以 `X-Aioj-Client-Ip` 转给下游，客户端自带的同名头先被删掉。
- 按地址：登录/刷新/注册、提交、AI 对话、代码运行、出题作业五类写请求各有一个 Redis 令牌桶，按“类别 + 客户端地址”计数，IPv6 按 /64。默认值按“一个地址后面十来个人”定；机房这类很多人共用出口的地址可以放进“共享网段”名单，不做按地址的限制。Redis 不可用时放行并计数。
- 按用户：登录失败按“账号 + 地址”计数（15 分钟 5 次锁 15 分钟），另有账号合计的上限（15 分钟 50 次），别处输错密码锁不住你；每人每分钟 30 次提交；每人同时最多 2 个 AI 回答，加上原有的 AI 额度；代码运行的每分钟、每天次数和间隔；每个管理员排队和执行中的出题作业最多 3 个。
- 超限一律返回 HTTP 429、错误码 42900、`Retry-After` 和错误键（`errorParams.retryAfterSeconds` 里也有秒数），页面显示是哪一种限制和大约多久后再试。所有阈值都能用环境变量调整。

## 判题隔离

problem-service 只发布任务，judge-worker 只编排并调用 Sandbox。Sandbox 不能访问 Docker socket、host network、业务目录、数据库、JWT、AI 或部署秘密；测试包只读，临时工作区独立，CPU、内存、PID、时间、输出和日志有界。

### 特权 Sandbox 风险

当前 go-judge 集成使用 `privileged` 容器。正常代码受命名空间、cgroup 与执行限制约束，但成功利用 Sandbox、Docker、容器运行时或 Linux 内核漏洞仍可能：

- 获得宿主机 root 等价控制；
- 读取或篡改数据库、用户数据、密钥和令牌；
- 修改评测结果、镜像、容器或内部流量；
- 访问 MySQL、Redis、RabbitMQ 与业务服务；
- 耗尽 CPU、内存、进程、磁盘或网络；
- 建立宿主机级持久化。

单节点部署扩大了该风险的影响范围和单点故障范围。内部网络、只读挂载、资源限制和秘密隔离是必要补偿控制，但不能让单节点与独立判题节点达到等价安全。

### agent-sandbox

为 Agent 工具执行新增的 agent-sandbox 复用判题 Sandbox 的镜像，同样以 `privileged` 运行，上面列出的后果对它同样成立。补偿控制：

- 只接入 internal 网络 `agent-sandbox-net`，不发布端口；这个网络里另外只有 agent-executor，它不持有数据库、消息队列、JWT 或 AI 秘密；
- MySQL、Redis、RabbitMQ、业务服务和判题 Sandbox 都不在它的网络里；
- ai-service 只能经 app-net 调用 agent-executor（用 agent-executor 自己的令牌），不接入任何沙箱网络，也不持有沙箱令牌；
- 根文件系统只读，`/tmp` 是有容量上限的 tmpfs，没有业务卷；PID、内存、CPU、输出和 copy-out 各有上限；
- 令牌与判题 Sandbox 分开。

gVisor（`runsc`）能否承载 go-judge、从而去掉 `privileged`，目前还没有评估，因为需要一台 Linux 主机。评估之前 agent-sandbox 保留 `privileged`，维护者已接受这一风险。

## AI 安全

- 模型和模型输出不可信，授权和工具执行在服务端。
- 所有模型调用经模型调用包，架构测试禁止旁路；每次调用留下观测记录。
- 私有题面、隐藏测试和无关个人数据不发送给 Provider。
- 问答的流式事件只带正文增量，以及工具的名称、状态和耗时；不带工具参数、工具结果和模型思考。比赛受限轮不流式，输出检查通过后才回放。
- 助教的代码工具只运行本轮选中的代码、题目页编辑器随本轮发来的代码或学生本人的提交，不运行模型给出的源码；比赛受限轮没有这些工具。
- 题目页的自测运行只用公开样例和学生自己的输入，不碰隐藏测试，不建提交记录；题目可见性和比赛上下文由服务端核对，运行受间隔、并发和次数限制。
- Prompt、工具结果和召回内容区分指令与数据来源。
- AI 查重与复盘是建议性证据，不能自动形成纪律处分或最终成绩。
- 记忆写入需要候选、证据、冲突检查和用户确认。
- 题目草稿的 workspace、用户、草稿、执行和工件归属由服务器绑定；模型不能通过工具参数选择或覆盖这些资源。
- DeepSeek 原始 `reasoning_content` 仅在当前工具循环内存中使用，不进入数据库、日志、审计或前端。
- 代码、生成器、测试包和自测运行只经 agent-executor 进入 agent-sandbox，不进入判题 Sandbox；隐藏用例仅向模型返回聚合结果，通用工具审计不保存原始代码或进程输出。
- 人工 ZIP 需要 SHA、manifest、路径、软链接、重复项和解压体积检查。解压时按实际写出的字节计数，单条和整包都有上限，压缩炸弹在这一步被拦下；不再按压缩比拒收，因为真实的大数据测试（大量相同的数）压缩比远超固定阈值；未经全包执行验收的导入必须显式标为 `MANUAL_UNVERIFIED`。

## 秘密与交付

四个方向变量为 `AIOJ_INTERNAL_TOKEN_AI_TO_PROBLEM`、`AIOJ_INTERNAL_TOKEN_JUDGE_TO_PROBLEM`、`AIOJ_INTERNAL_TOKEN_PROBLEM_TO_AI`、`AIOJ_INTERNAL_TOKEN_PROBLEM_TO_JUDGE`，每个目标另有可选 `_NEXT`；执行器使用 `AGENT_EXECUTOR_INTERNAL_TOKEN` 及入站专用 `_NEXT`。每个生产值由操作系统密码学安全随机数源独立生成（至少 32 字节），直接交付受限秘密存储；按“目标 NEXT → 调用方当前 → 目标提升当前并清空 NEXT”的顺序逐服务重启，不同时切换两端。

GitHub 只保存发布所需的受限部署身份与固定主机密钥材料；应用与 GHCR 读取凭据留在服务器 root-only 配置。生产使用不可变镜像 digest，不使用 `latest`，服务器不保存 Git 工作树。

## 恢复边界

生产备份只来源于生产服务器，并同时保护数据库、消息状态、测试包和必要产物。镜像回滚使用当前数据卷；成功执行的 Flyway 不自动回滚。恢复或清理是独立授权操作，不能由应用发布顺带执行。

## 责任披露

安全问题应通过维护者已验证的私密渠道报告。不得在公开 Issue 中发布凭据、个人数据、隐藏测试、私有源码、基础设施细节或可直接利用的攻击步骤。
